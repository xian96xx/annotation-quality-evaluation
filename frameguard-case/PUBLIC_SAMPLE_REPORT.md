# 公开样本实测：FrameGuard 规则与覆盖边界

## 目的和数据

检查 FrameGuard 原有规则在稀疏标注上如何报告覆盖，以及对人为制造的明确越界能否提示。使用 [USC MCL Drone Dataset](https://mcl.usc.edu/mcl-drone-dataset/) 的 `Drone_frames/img/`，从官方列出的 [Hugging Face 数据包](https://huggingface.co/datasets/uscmcl/MCL_drone_dataset/tree/main) 读取一基帧 1、16、31、46、61 及对应参考框。数据集说明为 1920×1080、15 FPS，每 15 帧一个框；本次不是逐帧真值。版权和许可见 [第三方许可](THIRD_PARTY_LICENSES.md)。

数据来源网站写坐标为中心点格式，但人工观察这 5 帧时，按左上角加宽高绘制的框更贴合目标。本实验采用后者，记录为**仅限本小样本的解释**；其他序列必须独立核实。输入轨迹 ID `drone` 为本次指定，非数据集原有 ID。

## 执行方法与结果

用本机原 FrameGuard 的 Python 规则引擎，构造 61 帧的输入：上述 5 帧有参考框，另外 56 帧标记为没有标注文件；不把没有框的帧当成目标消失。规则 FPS 设为官方标示的 15。它只接收框坐标，没有运行检测模型、X-AnyLabeling 或产品 UI，也未分析像素内容。

| 情况 | 实际结果 | 正确理解 |
|---|---|---|
| 原参考框 | 0 条提示；5 帧有框、56 帧无标注 | 没有提示不等于数据全对；帧间连续性有 4 个因未标注帧而抑制的间隙 |
| 独立副本：仅把第 31 帧框左边界设为 -1 px | 1 条 `bounds`，零基帧 30，标记为确定性 | 人为构造的 1 个几何越界被提示；不是发现真实标注错误，也不是统计意义的检出率 |

独立副本没有写回原数据。规则不验证框是否包住真实目标或能否发现从未标出的目标；对于跳变和遮挡也仍需画面复核。该实验只有一个序列、一个人为注入的错误与一个对照，不能推断真实业务误报率、漏报率、准确率或节省的时间。

## 可复现性与限制

执行环境 Windows、Python 3.12.5，FrameGuard CPU 规则 `frameguard-cpu-1.0.1`。这里不分发原 FrameGuard 源码或数据，本报告的原引擎运行需要原项目，无法仅凭本仓库独立复现。下方独立脚本只复现几何对照，不等同原引擎或覆盖判断。另有独立整理的公开样本插值对照案例，可单独复现简单基线。

下一步用许可清楚的多个序列，事先定义缺陷注入和事件匹配方式，人工核对边界、遮挡、出画及 ID 语义；把发现的候选与未提示样本都纳入复核，记录误报、漏报和时间。软件原项目、对外描述和数据发布仍需权属审阅。


本目录可复现的独立几何对照（Python 标准库）：

```bash
python fetch_public_reference.py
python public_geometry.py --annotation local/usc_groundtruth_rect.txt
python -m unittest discover -s tests -v
```

下载脚本只在 `local/` 保存公开参考标注（被 `.gitignore` 忽略）；该文件的 SHA-256 在运行时核对。独立几何脚本实测对 5 个参考框给出 0 项，对注入副本给出 1 项越界，与原引擎在这一条规则上的观察一致，不覆盖时序规则。5 项自动测试通过。

## 使用实际跟踪输出的覆盖对照

本次另把同一公开序列上**定制版 X-AnyLabeling 工作器的 61 帧输出**（两个关键帧与三个关键帧各一组）送入原 FrameGuard 规则，均输出 0 条候选。留出帧第 16、46 帧相对数据集参考框最大边界差约 21.5–23.25 px。FrameGuard 本身不校验框与真实目标是否贴合，因此这一现象说明的是**功能覆盖边界**，不是已经证实的误报或漏报；参考框与细部标准仍需人工核对。两组结果仅作单序列案例，不能代表全部业务效果。
