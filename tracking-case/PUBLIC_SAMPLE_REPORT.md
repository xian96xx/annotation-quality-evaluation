# 实测报告：公开无人机样本与稀疏关键帧

## 样本、来源与范围

2026-10-27 使用 [USC MCL Drone Dataset](https://mcl.usc.edu/mcl-drone-dataset/) 的公开序列 `Drone_frames/img/`。官方页面说明其视频为 1920×1080、15 FPS，标注每 15 帧提供一次；本次从官方列出的 [Hugging Face 压缩包](https://huggingface.co/datasets/uscmcl/MCL_drone_dataset/tree/main) 按需读取标注文件和 5 张图像，没有整包下载。本目录不分发未修改的原始图片或标注，但另附有按许可制作的裁剪叠框衍生图，计算结果已保存为 [public_comparison.csv](reports/public_comparison.csv)。原数据由 USC 发布；版权和许可见 [第三方许可](THIRD_PARTY_LICENSES.md)。

5 张图片对应一基帧号 1、16、31、46、61，文件 `groundtruth_rect.txt` 前 5 行顺序对应这些帧。人工查看叠框时，5 张图上的目标均位于按左上角 `(x,y,w,h)` 解释的框附近。**来源网页写的是中心点格式；本次按左上角解释只是对该序列这 5 个样本的观察，不足以证明全部文件格式。** 若按中心点解释，第 1 帧可见偏移。其他序列应先目视核验，不能盲目照搬。

原始文件 SHA-256：`2473a0a2d8d1a4f5cd5544e69dd120436393737189b4fdcfc27bf627844877b7`。五张图片曾在本机核查；其中两个留出帧的裁剪叠框衍生图见 [定制工作器实验](TRACKING_EXPERIMENT.md)。参考框可能包含标注误差，只作为数据集参考，不是无误的真值。

## 对照设计

比较独立实现的**线性插值基线**，并非 X-AnyLabeling 的输出或内部算法。两关键帧使用第 1、61 帧的参考框；三关键帧使用第 1、31、61 帧。共同留出第 16 和 46 帧，各方法仅与对应的数据集参考框比较；留出帧不参与插值。IoU 为两框交集面积除以并集面积；最大边界偏差是左右上下四条边坐标差绝对值的最大值，单位为原始图像像素。

| 留出帧 | 两关键帧 IoU | 三关键帧 IoU | 两关键帧最大边界偏差 | 三关键帧最大边界偏差 |
|---|---:|---:|---:|---:|
| 16 | 0.6821 | 0.6116 | 27.75 px | 37.00 px |
| 46 | 0.6114 | 0.5800 | 29.75 px | 45.50 px |

这个例子里加入中间关键帧后，两个留出帧的简单线性插值更接近还是更偏离参考框？**两处都更偏离**。这与合成演示中增加锚点改善结果形成对照，说明不能先验认为增加关键帧必然改善；可能原因包括运动非线性或参考框本身的不一致，未做根因验证。样本只有一个序列、两个留出帧，不具统计代表性，不足以判断真实软件优劣；IoU 和边界差也不能证明细桨完整。

## 复现

Python 3.10+ 标准库；在本目录执行：

```bash
python fetch_public_reference.py
python public_study.py --annotation local/usc_groundtruth_rect.txt --out reports/public_comparison.csv
python -m unittest discover -s tests -v
```

脚本通过 HTTP Range 从第三方 3.95 GB 压缩包读取目录与指定小文件，验证 SHA-256，将原参考标注存入 gitignored 的 `local/`；不自动下载图像。远端支持、网络状态和压缩包版本可能变化，脚本在哈希不匹配时停止。研究者如需人工核对图片，应从官方来源另外取得符合许可的原图；不要提交公司文件或把没有审查的公开图像提交到仓库。

运行环境为 Windows、Python 3.12.5；`public_study.py` 使用标准库，5 项自动测试通过。人工核对是单次查看，不是双人盲评。下一步应扩展不同序列和困难场景，并补充真实 X-AnyLabeling 输出；要评估实际标注效率需记录工作流及人工复核耗时。
